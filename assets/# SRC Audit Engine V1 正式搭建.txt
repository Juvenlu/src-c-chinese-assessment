# 五、Language Unit 正式实现

将 Phase 2–3 已确认的 Language Unit 规则，从临时脚本迁移为正式 TypeScript 模块。

核心定义：

> Language Unit = 可作为整体理解和学习的自然中文词或固定词汇单位，最少2个汉字。

必须满足：

* ≥2个汉字
* 自然中文词或固定词汇单位
* 语义完整
* 纯中文字符
* 不是完整句子
* 不是临时自由短语

支持：

1. 普通词
2. AA / VV / V一V 重叠
3. `-们`
4. `-子`
5. `-头`
6. 三字自然词
7. 专有名词
8. 成语/四字固定词
9. 补语结构，如 `跳出来`
10. 固定搭配，如 `越来越喜欢`
11. SRC词库中的完整词
12. 故事核心专有名词

排除：

1. 单字
2. 伪词
3. 临时自由短语
4. 完整句子
5. 单纯句型
6. 跨标点字符串
7. 整体数量+名词短语
8. 整体 `得+补语`

---

# 六、Language Unit 匹配规则

必须使用：

> **Candidate Construction → Eligibility Filter → Longest Match → Classification**

规则：

1. 先建立候选 Language Units。
2. 删除不符合定义的候选。
3. 采用最长匹配。
4. 同一文本位置只能属于一个 Language Unit。
5. 不允许重叠。
6. 不允许嵌套重复统计。

例如：

```text
小猴子
```

不能同时统计：

```text
小猴
猴子
小猴子
```

最终只保留符合规则的最长有效 Language Unit。

# 七、四级分类正式实现

正式使用以下四类：

## I

当前孩子/目标等级下的已掌握语言单位。

---

## I+1A

最高优先级的 +1：

> Language Unit 中所有汉字均属于当前 SRC 字符基础，但该完整词/固定词汇单位不属于当前 SRC 词汇基础。

例如：

```text
看看
小猴子
猴子们
跳出来
越来越喜欢
```

---

## I+1B

第二级 +1：

> Language Unit 中包含1个 SRC-out 字符，其余字符属于已掌握字符基础，并形成自然语言单位。

---

## High-load

高负荷单位：

> Language Unit 中包含≥2个当前 SRC-out 字符。

High-load 是独立类别。

**禁止把 High-load 称为普通 I+1。**

统计时：

```text
Narrow I+1 = I+1A + I+1B

Non-I = I+1A + I+1B + High-load
```

---

# 八、分类优先级

必须遵守：

```text
I
↓
I+1A
↓
I+1B
↓
High-load
```

这里表示语言负荷层级。

对于真正的 +1：

```text
I+1A
>
I+1B
>
High-load
```

High-load 不属于普通 +1。

# 九、Character Audit

正式实现：

```text
auditCharacters(text, targetLevel)
```

至少输出：

* total Chinese characters
* SRC-in character count
* SRC-out character count
* SRC-out occurrence count
* unique SRC-out characters
* External Character Occurrence Rate
* SRC-in unique characters
* SRC-out unique characters

公式：

```text
External Character Occurrence Rate
=
SRC-out Chinese Character Occurrences
/
Total Chinese Character Occurrences
```

注意：

不要把 unique external character rate 当成主要难度指标。

# 十五、Child-specific Audit

V1 正式支持：

```text
auditForChild({
  targetLevel,
  knownCharacters,
  knownWords,
  pages
})
```

但必须遵守：

### 不得把 `stable_char_count` 当成具体已知字集合。

### 不得把测试中没有出现的字符直接判定为“不认识”。

V1 的 Child-specific Audit 应区分：

```text
confirmed_level baseline
+
explicit weakness signals
```

其中：

* SRC等级提供通用基础
* 明确答错的字/词作为 Weakness Signal
* 未测试项目保持等级基线
* 不推断未测试字符一定未知

建议数据结构：

```text
weak_character_signals
weak_word_signals
```

而不是简单：

```text
unknown_characters
```

如果当前数据库还没有这种结构：

> V1 可以接受函数参数形式，不要求本阶段修改完整测评数据结构。
