# SRC100 / SRC300 / SRC500 / SRC800 全等级一致性最终审计与修复指令

## 一、任务目标

现在不要继续针对某一个页面做局部修复。

请对 SRC100、SRC300、SRC500、SRC800 四个等级进行一次完整的“注册 → Quick Assessment → 创建个人档案 → Hub → Growth Map → 正式 SRC 测试 → Results → Growth Map confirmed → 退出登录 → 重新登录 → Hub 数据恢复”的全链路一致性审计。

目标是确认：

> **SRC300 已经通过的完整数据链路，必须真正做到 SRC100 / SRC300 / SRC500 / SRC800 四个等级均由同一套动态逻辑驱动，而不是 SRC300 可以工作、其他等级靠 fallback 或硬编码勉强工作。**

本次任务遵循以下最高原则：

### 原则 1：不要改变已经确认正确的核心算法

严禁未经确认修改：

* Quick Assessment 算法
* LevelService 等级计算逻辑
* SRC 各等级的核心判定规则
* 单字/词组抽样算法及比例
* 正式测试的认识/不认识题型
* confirmed level 计算规则
* 趣味闯关算法
* XP 逻辑
* SRC 字库内容本身

除非审计明确证明某一处本身就是 Bug。

### 原则 2：禁止通过增加 fallback 掩盖问题

如果某个等级无法正常运行，必须找到真正原因。

不要采用：

* 强制 fallback 到 SRC300
* 强制 fallback 到 SRC100
* 用另一个等级的数据代替当前等级
* 用默认数字伪造测试结果
* 用 UI 文案掩盖数据库或数据链路问题

### 原则 3：所有等级必须动态读取当前 level

凡是与等级有关的：

* 字库
* 词库
* 抽样
* 题量
* session
* answers
* results
* Growth Map
* confirmed level
* recommended level
* 下一阶段
* Hub

都必须确认是否真正使用当前 `level`，不能存在 SRC300 或 SRC100 专属硬编码。
