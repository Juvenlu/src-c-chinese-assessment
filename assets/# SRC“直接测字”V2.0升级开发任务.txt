## 一、任务目标

现有平台已经完成：

1. 用户注册/登录
2. 游客“直接测试”
3. SRC100 / SRC300 / SRC500 / SRC800四级累积字词库
4. SRC字词库审计
5. 基于minimum_src_level建立独立Assessment Item Pool

现在请在现有代码基础上，对：

# “直接测试 / Direct Test”

进行第二阶段升级。

> **让游客在3–5分钟内自然完成一次中文字词基础体验，同时让系统能够更加可靠地判断孩子的SRC中文阅读字词基础，并为后续i+1绘本推荐提供可靠起点。**

请优先复用现有代码、数据库、题池和UI组件，不要重构整个项目。

SRC100 ⊂ SRC300 ⊂ SRC500 ⊂ SRC800

一个字词可以出现在多个SRC等级中，但：

# 直接测试必须按照minimum_src_level归类。

SRC100
SRC300

# 十一、不要仅根据单次正确率机械决定是否升级

每一级只有：

6个单字 + 3个词语。

因此样本仍然较小。

不能简单：

“5/6 = 83% → 自动认为完全掌握”

必须增加：

# 边界/置信度判断

例如：

### 明显通过

单字、词语均明显超过阈值

→ 可以升级

### 明显未通过

两项明显低于阈值

→ 停止升级

### 临界

例如：

单字接近阈值

或者：

单字通过但词语明显偏低

→ 追加边界确认题

---

# 十二、边界确认题

如果当前等级结果处于临界区域：

追加该等级题目。

追加题不得超过最大容量：

单字最多30

词语最多15

追加题必须：

* 来自同一minimum_src_level
* 优先使用尚未出现的题目
* 不与本次session重复
* 核心题优先
* 保持题型多样性

# 十三、Confidence Booster规则

现有题池设计中包含：

# 信心缓冲题 / confidence booster

可以保留。

但必须特别处理：

> **confidence booster不能计入当前SRC等级的能力评分。**

例如孩子刚进入SRC500：

可以出现一道SRC300核心题帮助孩子保持答题信心。

但数据库标记：

question_role = confidence_booster

scoring = false

该题：

* 可以显示给孩子
* 可以用于游戏体验
* 可以帮助降低挫败感
* 可以用于计算response time

但是：

# 不参与SRC500能力计算。

---

# 十四、禁止固定“简单→困难”的顺序

不要采用：

前20%简单
中60%混合
后20%困难

作为固定呈现顺序。

因为这会让孩子明显感觉：

> “题目越来越难。”

而且可能产生顺序效应。

正确方式：

# 在符合题库质量规则的前提下随机化。

随机化同时满足：

1. 核心题优先
2. 适量补充题
3. 避免连续相同部首
4. 避免连续同语义场
5. 避免连续相似字形
6. 避免同一个字词重复
7. 不出现明显的难度阶梯

# 四十一、最终产品原则

请在代码和项目文档中保留以下原则：

> **孩子在体验，系统在测量。**

> **测试过程中，孩子不需要知道当前题目属于哪个SRC等级。**

> **SRC等级是后台测量尺度，不是孩子测试过程中的提示信息。**

> **单字能力和词语能力必须分别测量。**

> **单字能力不能掩盖词语能力不足。**

> **最终阅读基础应优先反映孩子能够稳定使用的字词基础，而不是最高偶然答对的题目等级。**

> **游客快速测试的最终目的不是给出一个看似精确的数字，而是找到一个足够可靠的阅读起点，并把孩子自然地引导到下一步i+1中文阅读。**
