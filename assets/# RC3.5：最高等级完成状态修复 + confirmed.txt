# 五、RC3.5 最小修复方案

当前 `getConfirmedLevel()` 如果仍然是：

```ts
export function getConfirmedLevel(latestFormal) {
  if (!latestFormal?.stable_char_count) return null;

```

则修改为：

```text
countLevel = numToLevel(stable_char_count)

    两者中 Level Mapping 更高的等级
```

```text
confirmed_level = max(countLevel, testLevel)
```

或者：


必须使用：

```text
level-service.ts
```

中的统一 Level Sequence / Level Mapping。

例如：

```text

SRC300
SRC500
SRC800
```

通过统一索引比较。

# 六、建议的 getConfirmedLevel 逻辑

请根据当前项目实际 Level Service 结构实现，不要机械复制下面代码。

逻辑必须等价于：

```ts
export function getConfirmedLevel(latestFormal) {
  if (!latestFormal) return null;

  const countLevel =
    latestFormal.stable_char_count
      ? numToLevel(latestFormal.stable_char_count)
      : null;

  const testLevel =
    latestFormal.level ?? null;

  if (!countLevel) return testLevel;
  if (!testLevel) return countLevel;

  return getHigherLevel(countLevel, testLevel);
}
```

其中：

```text
getHigherLevel()
```

如果当前 Level Service 已经存在类似能力，优先复用。

如果不存在，可以在 `level-service.ts` 内采用最小方式实现。

```text
SRC100 < SRC300 < SRC500 < SRC800
```

必须继续保持：

> **Level Service 是 Level Mapping 的唯一来源。**
