# Phase 5B.1 — Personalization Causality Validation

## 一、任务目标

在现有 Phase 5B 基础上，验证：

> **同一 Master Story + 同一 SRC Level + 不同孩子 → 是否产生真正由 Child Reading Profile 驱动的、有教育意义的个性化语言差异。**

本阶段重点不是追求“文本不同”，而是验证：

**Child Data → Child Reading Profile → Prompt → Generation → Audit**

这条链路是否真正产生可解释、可重复、可审计的个性化结果。

---

# 二、严格限制

本阶段：

1. 不修改 Master Story。
2. 不修改 Master Image。
3. 不修改 Emma 已冻结的 Golden Sample：

   * rewrite_id = 9
4. 不修改 Audit Engine V1 核心判定规则，只允许修复明确的 bug。
5. 不重新设计 i+1 四级体系。
6. 不制定新的正式 High-load / I+1A / repetition 阈值。
7. 不引入 Multi-Agent。
8. 不引入复杂 Adaptive Algorithm。
9. 不引入 AI 自动 Finalization。
10. 不改变 `confirmed_level` / `estimated_level` 的语义。
11. 不把 `stable_char_count` 当作孩子实际认识的全部汉字。
12. 不因为测试失败而人为修改数据，使结果“通过”。
13. 所有实验必须保留原始生成文本和 Audit 结果。
14. 本阶段输出是“验证报告”，不是重新定义产品标准。

# 十七、最终结论只能使用以下三种之一

## PASS

只有在：

* 数据完整；
* Hellenna 等级无歧义；
* Generic Ablation 显示 Child Profile 确实产生有意义影响；
* 同孩子随机生成差异与跨孩子差异可以清楚区分；
* Volume validation 正常；
* Proper Name Protection 正常；
* Frontier validation 正常；

才可以：

```text
Phase 5B.1 = PASS
```

并建议进入 Phase 5C。

---

## CONDITIONAL PASS

如果：

* 技术链路正常；
* 已经存在一定 Child Profile 影响；
* 但因样本少、Weakness Signal 太弱、随机性较大等原因，还不能证明稳定因果关系；

则：

```text
Phase 5B.1 = CONDITIONAL PASS
```

不得进入复杂个性化算法开发。

应继续增加真实样本。

---

## FAIL

如果：

* Child Profile 实际没有进入生成；
* Generic 与 Personalized 无法区分；
* Hellenna 数据仍存在等级冲突；
* Proper Name 仍会被拆分；
* 超限文本仍可直接进入 final；
* Frontier 仍出现非法词；
* 或 Master Story 被生成器修改；

则：

```text
Phase 5B.1 = FAIL
```

必须先修复。

---

# 十八、最终原则

本阶段最重要的不是：

> “两个孩子生成出来的书必须不同。”

而是：

> **只有当孩子的数据不同，并且这种数据差异能够合理解释语言选择差异时，才算真正的个性化。**

因此最终验证逻辑：

```text
Same Child
   ↓
Random Variation Baseline
   ↓
Generic vs Personalized
   ↓
证明 Child Profile 是否产生影响
   ↓
Different Children Same Level
   ↓
验证 Child-specific Difference
```

最终目标：

```text
不是“AI会改写”
而是
“AI会根据孩子的数据进行可解释的语言适配”
```

完成后不要自行进入 Phase 5C。

先提交完整 Phase 5B.1 Validation Report。
