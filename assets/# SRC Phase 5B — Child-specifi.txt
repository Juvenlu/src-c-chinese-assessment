# SRC Phase 5B — Child-specific Generation Validation

## 一、任务目标

现在正式进入 SRC「i+1 定制绘本」Phase 5B。

目标不是继续设计理论，也不是修改 Audit Engine V1，而是验证：

> **同一个 Master Story + 同一个 SRC 等级 + 不同孩子 → 是否能够生成具有真实、合理、可审计差异的个性化语言版本。**

核心验证：

```text
同一 Master Story
        ↓
同一 confirmed_level
        ↓
不同 Child Profile
        ↓
Child-specific i+1
        ↓
生成语言版本
        ↓
Audit Engine V1
        ↓
横向比较
```

---

# 二、必须遵守的核心原则

## 1. 不改变 Master Story

Master Story 是唯一故事源。

禁止：

* 增加故事事件
* 删除核心事件
* 修改人物
* 修改人物关系
* 修改事件顺序
* 修改因果关系
* 修改结局
* 为了孩子语言水平改变故事内容

只能改变：

> **语言表达难度。**

---

## 2. 不改变 Master Image

每一页继续绑定原有 Master Image。

禁止：

* 重新生成图片
* 更换图片
* 修改图片
* 为语言版本选择不同图片

验证的是：

> Same Story + Same Image + Different Language

# 五、i+1正式定义

## I

当前 SRC 等级基础语言。

即：

> 当前 SRC 等级中已经掌握/允许作为基础的字符和词汇。

---

## I+1A

最高优先级。

定义：

> 所有汉字均属于当前 SRC 字符基础，但组成的自然词/固定语言单位不属于当前 SRC 词汇基础。

典型：

```text
看 → 看看
小 + 猴子 → 小猴子
猴子 + 们 → 猴子们
跳 + 出来 → 跳出来
越来越 + 喜欢 → 越来越喜欢
```

---

## I+1B

第二优先级。

定义：

> 一个 SRC 外字符 + 其他已知字符组成自然词/语言单位。

---

## High-load

严格控制。

定义：

> 一个自然语言单位中包含 ≥2 个当前 SRC 外字符。

High-load：

* 不是普通 I+1
* 不应大量使用
* 不因“增加学习量”而主动堆积

必须区分：

```text
Story-required
Valuable
Non-essential
```

---

# 六、个性化原则

正式采用：

```text
Confirmed Level
      ↓
Level Baseline
      ↓
Individual Weakness Signals
      ↓
Child Reading Profile
      ↓
Personalized i+1
```

## 非常重要

不要把：

```text
stable_char_count
```

当成孩子完整的已知字表。

不要假设：

```text
confirmed_level = SRC300
```

就代表系统知道孩子精确掌握 SRC300 的每一个字符。

目前测试数据中的：

```text
knownCharacters
```

可能只是抽样测试结果。

因此 Phase 5B 必须优先使用：

```text
confirmed_level
+
weakness signals
```

进行个性化。

---

# 七、Weakness Signal定义

不要把：

```text
wrong answer
```

永久定义为：

```text
unknown
```

正式称为：

> Weakness Signal

含义：

> 测试中出现错误，说明该字/词存在掌握不足或稳定性不足的信号。

因此：

```text
weak_character_signals
weak_word_signals
```

只能作为个性化的重要参考。

不能因此改变孩子的 confirmed_level。

# 十一、生成策略

对于每个孩子：

## Step 1

确定：

```text
confirmed_level = SRC300
```

建立 SRC300 baseline。

## Step 2

读取孩子：

```text
knownCharacters
weakCharacterSignals
knownWords
weakWordSignals
```

## Step 3

从 Master Story 中寻找适合个性化处理的 Language Units。

优先顺序：

```text
1. Known Character → New Vocabulary
2. 高频、实用词
3. 故事相关词
4. 常见搭配
5. 常见句式
6. 单个新字符
```

## Step 4

优先使用：

```text
I+1A
```

其次：

```text
I+1B
```

严格控制：

```text
High-load
```

## Step 5

如果某个孩子存在明确 Weakness Signal：

例如：

```text
某词/字 = weakness signal
```

则在该词/语言单位适合当前 Master Story 的情况下：

* 可以降低难度
* 可以换成更熟悉表达
* 可以减少该单位的使用
* 可以使用已知字符构成的 I+1A 替代表达

但：

> 不得为了制造差异而强行修改自然语言。

# 十二、非常重要：不要强行个性化

如果：

```text
Child A
Child B
```

虽然数据不同，但：

* 两人的弱项与本故事无关
* 当前故事没有适合个性化的语言单位

那么：

> 两个孩子生成相同文本是允许的。

不能为了证明“个性化有效”而人为制造差异。

# 十七、必须进行“差异解释”

不能只报告数字。

必须列出：

### Child A 特有的语言处理

例如：

```text
A版本：
“特别”
```

原因：

```text
Child A 对其他表达掌握较好，
“特别”属于当前适合的 I+1B。
```

### Child B 特有的语言处理

例如：

```text
B版本：
“慢慢”
```

原因：

```text
B的已知字符组合能够自然形成“慢慢”，
属于 I+1A。
```

---

# 十八、必须进行反向检查

对于每一个真正产生差异的语言单位，检查：

```text
1. 是否来自 Master Story？
2. 是否改变故事事实？
3. 是否符合当前 SRC level？
4. 是否属于合法 Language Unit？
5. 是否符合 I / I+1A / I+1B / High-load 分类？
6. 是否与孩子 Weakness Signal 有合理关系？
7. 是否自然？
8. 是否有必要？
```

任何一项明显不成立，都标记：

```text
Invalid Personalization
```

---

# 十九、禁止使用“差异越大越好”

Phase 5B 的目标不是：

> 最大化两个孩子之间的文本差异。

正确目标：

> **最大化“有教育意义、可解释、自然”的个性化差异。**

因此：

```text
High difference ≠ Good personalization
```

而是：

```text
Relevant difference
+
Natural language
+
i+1 suitability
+
Story consistency
=
Good personalization
```

# 最终核心判断标准

Phase 5B不是验证：

> “AI能不能给两个孩子写出不同的故事。”

而是验证：

> **在同一个故事、同一个SRC等级、同一套图片下，系统能否根据不同孩子的真实中文基础和Weakness Signals，自然地调整语言难度，使每个孩子获得适合自己的i+1阅读版本。**

最终产品目标：

```text
Same Story
+
Same Image
+
Same SRC Level
+
Different Child Profile
↓
Different but Natural Language
↓
Auditable i+1
↓
Personalized Reading
```
