# SRC 工程治理与变更控制｜V1.0

## 标准状态
- VERIFIED：有代码、Production D1、实际 UI 等证据支持。
- PROPOSED：设计规范，待管理员确认并在代码中实施。
- UNKNOWN：尚无足够证据，必须核验，禁止当作既成事实。

## 环境与权限
Production 为真实用户数据；Preview/Sandbox 与 Production 必须隔离。严禁 Preview 误连生产 Worker；隔离守卫的实际部署状态每次按代码与环境核验，不预设 PASS。生产数据库写入、推送、上线、Finalize、Activate、迁移需逐项授权。只读阶段不得修改任何内容。

## 开发流程（拟采用统一标准）
需求与验收标准 → 能力/依赖检查 → 现状只读审计 → 最小方案 → 管理员批准 → Agent 在受控环境修改 → 静态检查/测试 → 变更审计 → 部署前核验 → 单独授权部署 → Production 只读验证 → 必要时真实 UI E2E → 归档证据。

## 变更控制
任何修改数据源、身份认证、数据库 Schema、生产 Worker、公开 API 契约、阅读完成规则、书籍名额、发布状态机，必须附影响分析、回滚方案和明确授权。禁止为了绕过阻塞私自更换技术路线。

## 报告模板
任务ID；前提；能力；只读证据；变更计划/执行范围；结果 PASS/FAIL/UNKNOWN；风险与未执行操作；唯一下一步。

## 标准更新
标准文件与业务代码一起纳入 Git 版本控制；标准修改走独立审查，不自动生效。生产验证记录保留任务 ID、日期、证据与结论，不记录密码/Token/Session。
